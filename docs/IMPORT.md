# Импорт отчётов ИЭК и Systeme Electric

В «Загрузить файлы» выберите **комплект XLSX одновременно**. Типы листов
определяются по заголовкам первых 12 строк; оригинальные имена из приложения к
кейсу поддерживаются, включая повреждённую кириллицу в именах Systeme.
Предпросмотр показывает тип и поставщика. Полное чтение выбранных таблиц
начинается по кнопке «Подготовить данные», после настройки сроков и подтверждения
ограничений. Затем доступны «Рассчитать», карточка, правка, утверждение и экспорт.

Для одного поставщика нужны продажи и остатки. Один «Путь ИЭК» распознаётся,
но не позволяет рассчитать заказ: UI перечислит недостающие отчёты. MOQ и
поставки желательны; сезонность распознаётся как справочный лист.
Не смешивайте исходные отчёты и подготовленные `sales.csv` и т. п. в одной загрузке.

| Отчёт | Преобразование |
|---|---|
| Месячные продажи | Код 1С → `sku`; месяцы → строки `date, qty`. «Итого» не включается. Текущий и будущие месяцы исключены. Явные нулевые месяцы сохраняются. |
| Динамика продаж | Используется только без месячного отчёта. Расходные движения имеют минус: знак обращается; возвраты уменьшают продажи. Данные агрегируются по товару и месяцу. Неизвестные типы документов блокируют импорт. |
| Месячные остатки | Последний месяц не позже даты расчёта. ИЭК — начальный остаток месяца; дата среза явно показана. Итоговый столбец не является остатком. |
| «Путь ИЭК» | Каждая колонка поставки → строки `sku, qty, eta`; ETA извлекается из «поступление до ДД.ММ.ГГГГ». |
| «Товар в пути» Systeme, TDSheet | Свободный остаток после резервов; дата среза из имени файла. «СЭ в пути 24.09» → ETA с годом отчёта. Месячные продажи с этого листа используются только без отдельного отчёта/динамики. |
| MOQ ИЭК | «Мин. разр. к отгр.» → минимальный заказ; это не кратность. |
| MOQ Systeme | «Кратность» → шаг упаковки; не подменяется нулевой колонкой из отчёта продаж. |
| Сезонность | Справочная. Движок строит сезонность из количественной истории; готовые коэффициенты не умножаются повторно. |

Код 1С сохраняется строкой, включая ведущие нули и подчёркивания. Для экспорта
используется артикул поставщика, если он найден; единицы измерения сохраняются.
Если единица неизвестна — «ед.», а не выдуманное «шт.». Количество заказа пока
целочисленное. Перевод метров в бухты или других единиц не выполняется.

Срок поставки и цикл заказа задаются отдельно для каждого поставщика.
Начальные 14 дней — настройка для проверки, а не факт из отчёта.
Пустые числовые ячейки принимаются за ноль после подтверждения пользователем;
товары, вовсе отсутствующие в таблице остатков, исключены из заказа с предупреждением.
Без строки MOQ применяется упаковка 1, минимум 0, с предупреждением.
Отрицательные остатки/поставки, нечисловые количества, дубли справочника и
неоднозначный поставщик вызывают понятную ошибку, а не молчаливую правку.

## Ограничения качества

- Месячные отчёты не содержат склада: все данные сводятся к «Все склады (сводный отчёт)».
- Остатки после указанного среза не восстанавливаются: нет полного журнала приходов и перемещений.
- Клиентов нет. Используется единый UNKNOWN, а продажи агрегируются помесячно;
  нельзя утверждать, что на этих данных распознаются разовые клиентские заказы.
- Нет точных stockout-интервалов и BOM: из месячного нуля они не выводятся.
- Категория Systeme берётся из «Категория 2026», если есть. В остальных случаях
  используется явная группа «ИЭК / Без категории» или «Systeme Electric / Без категории».
- Доверие к импортированным рекомендациям помечается низким; в обосновании
  и интерфейсе остаются ограничения. Перед закупкой нужен актуальный остаток
  и проверка менеджером. Пять приёмочных сценариев демонстрируются на синтетике.

Импорт проходит `app/partner_import.py` → временные CSV → `engine.io.load_data`.
Временные CSV удаляются; исходные книги не изменяются. Импорт хранится в памяти
сессии/кэше процесса. В журнале утверждения остаются настройки и снимок заказа.
Смена файлов, даты или сроков требует повторной подготовки и расчёта;
утверждение/экспорт старой рекомендации блокируются.

## Проверка

`python -m pytest app/tests/test_partner_import.py -q` проверяет синтетические
XLSX с теми же заголовками, нормальный сценарий до экспорта, частичный комплект,
ошибки количества, знак движений, отсутствие двойного счёта, ведущие нули,
нулевые месяцы и блокировку устаревшего расчёта. Структуры всех 12 приложенных
книг дополнительно проверены на ограниченных образцах первых 14 строк;
качество и полнота всех исходных записей этим не подтверждаются.
