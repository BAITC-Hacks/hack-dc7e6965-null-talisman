# UI — зона Амира

Интерфейс Streamlit для сценария из `docs/PLAN.md`: расчёт → карточка и график → ручная правка → утверждение → XLSX/CSV. Дополнительно страницы «Проверки» и «Аналитика».

## Запуск

Из корня репозитория в активном Python 3.11+ окружении:

```bash
python -m pip install -r app/requirements.txt
python -m streamlit run app/streamlit_app.py
```

Интерфейс подключён к настоящим `engine.io`, `engine.pipeline` и `engine.export`. При первом запуске автоматически создаются синтетические демоданные, если `sales.csv` ещё отсутствует. Фиктивной подмены результатов расчёта нет.

UI не требует API-ключа, доступа в интернет или LLM. Для сохранения утверждений нужны права на запись в `data/orders/`. Экспорт и подтверждение локальные, внешней отправки заказов нет.

## Интеграция с ядром

Единственная точка адаптации: `app/backend.py`.

Подтверждённый планом контракт:

- `engine.pipeline.recommend(data, params) -> pandas.DataFrame` — колонки раздела 3 плана.
- `engine.pipeline.sku_series(data, sku, warehouse, today, growth_pct, forward_months) -> pandas.DataFrame` — `month, raw, clean, forecast, oneoff, stockout_days`. UI передаёт дату последнего расчёта и фактический `growth_pct` строки. Текущий месяц имеет горизонт h=0, как в расчёте заказа. История и будущие месяцы в одной таблице, отсутствующие значения — NaN. Для годовой сезонной проверки нужен прогноз 12 разных месяцев года.
- `params`: `today, warehouse, category, service_level, review_days, growth_override`, проценты в процентных пунктах (20 = 20%).

Подключённые функции:

- `engine.io.load_data(directory: pathlib.Path, today) -> (dict[str, DataFrame], list[str])`. Загрузчик отвечает за валидацию, обезличивание, BOM и приведение типов; дата из UI ограничивает историю продаж; UI не обходит загрузчик. XLSX конвертируется во временный CSV перед вызовом. Временная директория удаляется после загрузки.
- `python -m data.generate` создаёт `data/demo/*.csv`. UI вызывает команду только когда `sales.csv` отсутствует; ограничение 60 секунд.
- При другом API загрузчика или расположении `sku_series` меняется только адаптер, а не расчётное ядро.
- `purchase_price` или `unit_cost` — необязательная закупочная цена в ₸. Без неё денежный KPI обозначен «Нет закупочных цен»: цена продажи из sales не выдаётся за закупочную.
- `app/orders.py` сохраняет утверждённый снимок; его выгрузка выполняется общими `engine.export.export_xlsx` и `export_csv`. Оба формата содержат ручные правки, исключают нулевые количества и защищают текстовые ячейки от выполнения формул. Листы XLSX разделяются по ID поставщика, даже если названия совпадают.

Обязательные файлы при загрузке: `sales`, `stock`, `products`, `suppliers`. Дополнительные: `in_transit`, `stockouts`, `growth`, `bom`. Каждый файл CSV (UTF-8, запятая) или XLSX (первый лист), имя файла совпадает с именем таблицы. Семантическая валидация и требования к дополнительным файлам остаются в `engine.io`.

## Утверждение и экспорт

- Редактируется только целое количество ≥0; нулевые строки исключаются из выгрузки.
- JSON содержит автора, время UTC, параметры, исходное количество, итоговое количество и признак ручной правки.
- У каждого утверждения уникальное имя `{timestamp}_{supplier}_{id}.json`, старые версии не перезаписываются. Это уточнение имён из плана предотвращает потерю истории при двух утверждениях за день.
- Изменение строки после утверждения аннулирует разрешение на экспорт текущего заказа. Новый расчёт очищает утверждения текущего экрана; сохранённые файлы остаются.
- При изменении параметров экспорт блокируется до нового успешного расчёта.
- Общий экспорт включает только утверждённых поставщиков; их число показано явно.
- Формат: `Артикул; Номенклатура; Склад; Количество; Ед.; Поставщик; Срочность; Обоснование`. XLSX: отдельный лист на поставщика. CSV: `;`, UTF-8 BOM. Значения строк защищены от выполнения формул табличным редактором.
- Журнал сохраняется на диск, но восстановление редактора после перезапуска приложения в этот объём работ не входит. Повторные утверждения хранятся как новые версии, а не отправляются поставщику.

## Проверки

`app/checks.py` выполняет сценарии раздела 6 плана над копиями таблиц. Изменяет остаток, поставки в пути, категорию, прирост, stockouts и продажи BOM. Проверяет разовый заказ, восстановление спроса, полноту группировки и обоснований.

Сезонная проверка требует полный прогноз годового цикла и отдельно считает WAPE на трёх завершённых месяцах: отложенные продажи и будущие периоды отсутствия не передаются модели; для каждого отложенного месяца берётся месячный прогноз через `sku_series`, без подмены сроков поставки. Сравнение — с постоянным средним исторических продаж. Это UI-проверка по сценарию плана, не импорт тестов Никиты и не замена его `pytest`.

При проверке BOM удаляются и продажи комплектов, и уже развёрнутые строки компонентов (`client_id=BOM`). Для влияния категории используется SKU с искусственно укороченной до 12 месяцев историей: зрелые SKU могут законно использовать собственную сезонность. Разовая продажа добавляется в завершённый месяц; дополнительно проверяется увеличение исключённого сверхобъёма.

**Уточнение к разделу 6 первоначального плана:** проверка stockout сравнивает `forecast_horizon`, как текущий `tests/test_acceptance.py`, а не требует роста `need_raw`. Восстановление спроса может уменьшать вариативность и страховой запас, поэтому увеличение итоговой потребности не гарантируется. Это изменение критерия отражено на странице «Проверки»; исходная строгая формулировка плана не считается отдельно доказанной.

Статусы: зелёный — критерий выполнен, красный — не выполнен, белый — нет достаточных данных, жёлтый — ошибка выполнения. Отсутствие эталонного SKU не считается прохождением.

## Проверка UI

В том же окружении:

```bash
python -m pip install pytest
python -m pytest app/tests -q
```

Тесты Streamlit AppTest проверяют путь расчёт → правка → утверждение → экспорт, пустое имя, изменение утверждённого заказа, смену параметров и отсутствие ядра. Отдельно проверяются JSON, фактическое содержимое XLSX/CSV, нулевые количества, недопустимые числа, названия листов и защита от формул. Быстрые UI-тесты используют тестовый контракт. `tests/test_pipeline_contract.py` дополнительно проверяет настоящее ядро, соответствие графика заказу, все пять живых сценариев и путь до утверждённого JSON/XLSX/CSV.

Ручная интеграционная проверка: запустить приложение, рассчитать демоданные, открыть «Показать обоснование и график», изменить количество, указать имя, утвердить, открыть XLSX, проверить соответствие количества редактору; поменять количество ещё раз — кнопки скачивания должны исчезнуть. Затем открыть «Проверки» и выполнить все сценарии. Питч и сценарий — `docs/DEMO.md`.

## Сторонние компоненты

Streamlit — интерфейс и AppTest; pandas/numpy — таблицы и числовая валидация; Plotly — графики; openpyxl — XLSX; pytest — тесты. Использованы AI coding tools. UI не содержит модели машинного обучения, внешнего API или стороннего датасета. Данные демо и алгоритм предоставляет остальная команда.
