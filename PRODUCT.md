# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Streamlit (Python), server-rendered multi-page app. Custom visual work happens
through Streamlit's theming config (`.streamlit/config.toml`) and CSS injected
via `st.markdown(..., unsafe_allow_html=True)` — there is no separate frontend
framework, build step, or component library to replace.

## Users

Менеджер отдела закупа в ТОО «Электрокомплект» (электротехнический дистрибьютор,
ekt.kz). Работает за десктопом/ноутбуком, в рабочее время, часто параллельно с
Excel и 1С. Задача: раз в цикл (обычно ежемесячно, сейчас — вручную и нерегулярно)
понять, сколько и у какого поставщика заказать, не переплатив за лишний склад и
не упустив продажи из-за дефицита.

## Product Purpose

Null Talisman рассчитывает рекомендованные заказы поставщикам на основе истории
продаж, сезонности, остатков, товаров в пути и ограничений поставщиков — и
объясняет каждую рекомендацию, а не просто выдаёт число. Менеджер проверяет,
правит количество при необходимости, утверждает и выгружает заказ. Успех —
рекомендация, которой менеджер доверяет достаточно, чтобы утвердить её без
пересчёта в Excel.

## Positioning

Не «ещё один дашборд с графиками продаж» и не чёрный ящик с ML-прогнозом.
Каждое число прослеживается до конкретной причины: разовый крупный заказ
исключён (видно, чей и когда), дни без товара компенсированы (видно, сколько
восстановлено), сезонность и тренд посчитаны прозрачным статистическим методом,
не нейросетью. Конкурентный дашборд с «умным ML» не может честно показать
«почему именно 450, а не 400» — здесь это первая строка карточки позиции.

## Operating Context

- Источник данных: демо-синтетика (`data/generate.py`, детерминированный seed)
  или загрузка собственных CSV/XLSX по фиксированному контракту; отдельно —
  импорт «сырых» файлов от 1С/Excel через мастер (`app/partner_import.py`).
- Рабочий цикл: выбрать склад/категорию/дату → «Рассчитать» → просмотреть
  таблицу по поставщикам → открыть карточку позиции (график + текстовое
  обоснование) → при необходимости поправить количество вручную → указать
  ответственного → утвердить → скачать XLSX/CSV для дальнейшей загрузки в 1С.
- Отдельная страница «Проверки» — живая демонстрация пяти обязательных
  критериев трека (сравнение результата до/после изменения входных данных);
  страница «Аналитика» — обзор спроса по категориям.
- Решение об отправке заказа поставщику всегда остаётся за человеком — в
  продукте нет и не может появиться автоматической отправки.

## Capabilities and Constraints

- Расчёт: страховой запас, горизонт (срок поставки + цикл заказа), округление
  до упаковки/MOQ, срочность (`critical`/`high`/`normal`), доверие к прогнозу
  (`confidence`/backtest).
- Явно НЕТ денежной суммы заказа в базовом сценарии — в контракте данных нет
  закупочных цен, и продукт не подменяет их ценой продажи.
- Клиентские идентификаторы в данных всегда хэшированы (SHA-256) до попадания
  в UI или экспорт — сырые ID клиентов никогда не показываются.
- Контекст хакатона: HackAlem AI 2026, узкое окно на реализацию, синтетические
  демоданные — приложение явно маркирует их как синтетику, не выдаёт
  результаты на них за доказательство на реальных данных партнёра.
- Технический стек Streamlit ограничивает визуальную свободу: нет произвольной
  вёрстки макета/канваса, работа идёт через тему + CSS-переопределения
  стандартных компонентов Streamlit (кнопки, метрики, data_editor, expander,
  вкладки, файл-аплоадер).

## Brand Commitments

Имя продукта: **Null Talisman** (название команды на хакатоне, не финальный
коммерческий бренд — воспринимать нейтрально, не сочинять лишний сторителлинг
вокруг названия). Партнёр кейса: ТОО «Электрокомплект» (ekt.kz) — упоминается
как контекст задачи, не как заказчик визуального стиля.

## Evidence on Hand

- Реальный, работающий расчётный движок и полный пользовательский путь (не
  прототип на статике) — `app/streamlit_app.py`, `engine/*`.
- README с методологией и честными цифрами (WAPE, доля критичных позиций) —
  не маркетинговые заявления, а измеренные значения на демоданных.
- Тестовые/логотипные материалы, пресса, кейс-стади — отсутствуют, это
  хакатон-MVP; будущая работа не должна их выдумывать.

## Product Principles

1. Объяснимость выше эффектности — любой визуальный акцент обязан вести
   взгляд к обоснованию числа, а не отвлекать от него.
2. Сканируемость таблиц/карточек — менеджер просматривает десятки позиций
   подряд, плотность и ритм важнее «воздуха» ради воздуха.
3. Срочность видна с первого взгляда (critical/high/normal), но без
   тревожной, кричащей палитры — это операционный инструмент, не алерт-центр.
4. Ничего не эмулирует автоматизацию, которой нет: явные шаги подтверждения
   (правка → имя ответственного → утверждение) остаются заметными, не
   маскируются под «магическую» одну кнопку.
5. Синтетика vs реальные данные всегда визуально/текстово различимы — дизайн
   не должен стирать это разграничение ради красоты.

## Accessibility & Inclusion

Специфических требований пользователь не подтверждал. Обычный стандарт
контраста текста/фона (WCAG AA как разумный минимум для рабочего B2B-
инструмента) считается по умолчанию, без отдельного аудита в рамках этой
итерации.
